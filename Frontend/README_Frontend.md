# Frontend вебсайта «ЗАРЯ»

Инструкция по локальной разработке трёх независимых React-приложений. Текущее состояние проекта описано в [корневом README](../README.md), требования к интерфейсам в [архитектуре](ARCHITECTURE_Frontend.md), контракты и межкомандные договорённости в [документе интеграции](../Backend/BACKEND_INTEGRATION.md). Правила выполнения изменений находятся в [инструкциях агентов](AGENTS_Frontend.md).

## Окружение и установка

Нужны Git, Node.js **24.x**, npm **>=11**. Линия Node указана в `.nvmrc`, зависимости зафиксированы в `package.json` и `package-lock.json`. Все npm-команды ниже выполняются из `Frontend`.

```powershell
cd Frontend
npm ci
```

Для текущего участка с MSW сервер и БД не нужны. При работе с настоящим API требуется отдельно доступное серверное окружение.

## Запуск приложений

Каждое приложение запускается в своём терминале. Порты фиксированы: занятый порт вызывает ошибку, автоматического переключения нет. Серверы доступны только на `127.0.0.1`.

| Команда | Приложение | Адрес |
| --- | --- | --- |
| `npm run dev:web` | Публичный сайт, обычный API-режим | [5173](http://127.0.0.1:5173) |
| `npm run dev:web:mock` | Публичный сайт с MSW | [Новости](http://127.0.0.1:5173/news) |
| `npm run dev:cms` | Закрытая оболочка CMS | [5174](http://127.0.0.1:5174) |
| `npm run dev:moderation` | Закрытая оболочка модерации | [5175](http://127.0.0.1:5175) |

Два режима публичного сайта одновременно используют один порт, запускать нужно один из них. CMS и модерация пока не имеют mock-команд, авторизации и рабочих защищённых интерфейсов.

## Переменные окружения

Образец: [apps/web/.env.example](apps/web/.env.example). Для локальных значений можно скопировать его в `apps/web/.env.local`, который исключён из Git. После изменения окружения перезапустите Vite.

| Переменная | Значение и действие |
| --- | --- |
| `VITE_API_BASE_URL` | Предварительный API base, включает префикс; по умолчанию `/api/`. Для удалённого API можно задать абсолютный адрес с префиксом |
| `VITE_MOCK_SCENARIO` | Сценарий MSW, по умолчанию `default`; не влияет на обычный API-режим |
| `VITE_ENABLE_MOCKS` | Явный флаг включения. `true` задан в отслеживаемом `apps/web/.env.mock`, используемом `vite --mode mock` |

Моки запускаются только при `import.meta.env.DEV` и `VITE_ENABLE_MOCKS === 'true'`. Не задавайте этот флаг в `.env.local` или общем окружении для обычного API-запуска. Production не включает моки даже при `--mode mock`. Секреты в `VITE_*` запрещены: значения доступны браузеру.

## MSW и сценарии

MSW 3.0.3 подключён через официальный `msw/vite` при Vite 8.3.5. Worker обслуживается плагином при разработке, файла в `public` нет. React запускается после готовности перехвата запросов. При включённых моках виден индикатор «Тестовые данные».

| Сценарий | Поведение |
| --- | --- |
| `default` | 26 вымышленных новостей, при размере 12 получается три страницы |
| `empty` | Пустой список |
| `slow` | Задержка ответа 1500 мс |
| `error` | HTTP 503 |
| `network-error` | Ошибка соединения |
| `next-page-error` | Первая страница успешна, последующие возвращают 503 |

В PowerShell сценарий можно выбрать на время работы терминала:

```powershell
$env:VITE_MOCK_SCENARIO = "empty"
npm run dev:web:mock
# После остановки Vite (Ctrl+C):
Remove-Item Env:VITE_MOCK_SCENARIO
```

Неизвестное имя сценария останавливает mock-запуск. Обработчики и данные централизованы в `mocks`; материалы вымышлены и не являются текстом или лором игры. Состояние не сохраняется между перезагрузками. Авторизация, регистрация, CMS и модерация не моделируются.

Неизвестные HTTP-запросы внутри выбранного API-origin и API-префикса блокируются с явной ошибкой. Остальные ресурсы, в том числе Vite и изображения, пропускаются. Эта политика не является общим запретом любых внешних запросов.

## Проверки и сборка

| Команда | Назначение |
| --- | --- |
| `npm run lint` | ESLint |
| `npm run typecheck` | Строгий CheckJS/JSDoc во всех приложениях |
| `npm run test:unit` | Vitest и React Testing Library во всех приложениях |
| `npm run build` | Сборка трёх приложений |
| `npm run check` | Последовательно все четыре команды выше |
| `npm run test:e2e` | Отдельный запуск Playwright |

Vitest публичного приложения явно запускает Node-интеграцию MSW; после каждого теста сбрасываются обработчики, DOM и путь страницы, после набора тестов сервер перехвата закрывается. Тестовый base зафиксирован как `http://localhost:3000/api/`; настройка другого `VITE_API_BASE_URL` для тестов может потребовать отдельного согласованного изменения тестового окружения.

Сборки находятся в `apps/<имя>/dist`. Сборка web автоматически запускает [scripts/verify-web-build.js](scripts/verify-web-build.js), который проверяет имена и содержимое текстовых ресурсов на mock-worker, маркеры MSW и тестовых данных. Проверка не отключает копирование публичных ресурсов и не заменяет аудит всех возможных способов подключения моков. Для дополнительной проверки production при mock-mode:

```powershell
npm exec --workspace @zarya/web -- vite build --mode mock
node scripts/verify-web-build.js
```

Playwright проверяет стартовые оболочки и ширины 320/768/1024/1440 px, а не полноценную интеграцию новостей. Перед первым запуском нужен `npx playwright install chromium`. Команда `npm run test:e2e` запускает три обычных dev-сервера; уже работающие серверы не переиспользуются. Длительные браузерные проверки выполняются по правилам [AGENTS_Frontend.md](AGENTS_Frontend.md).

Последний зафиксированный результат этапа новостей от 28.10.2026: ESLint, CheckJS, 18 тестов и сборки трёх приложений прошли; проверены обычная production-сборка и сборка с mock-mode. Это исторический результат, а не подтверждение последующих изменений. Браузерные сценарии и настоящий API этим запуском не проверялись.
