# Как устроен frontend

## Приложения

`apps/web`, `apps/cms` и `apps/moderation` — независимые React-приложения со своими точками входа, Vite-конфигурациями и сборками. npm workspaces объединяет установку зависимостей и команды. Приложения не импортируют внутренний код друг друга.

Web использует FSD. CMS и модерация содержат простые оболочки с `app`, глобальными стилями и настройкой тестов. Команды запуска находятся в [README](../README.md).

Приватный пакет `@zarya/ui` находится в [`packages/ui`](../packages/ui). Все три приложения подключают локальные шрифты Zarya Poster и Zarya Text через `@zarya/ui/typography.css`. CMS и модерация используют из этого же пакета общий экран недоступности и передают подпись своего приложения. Компонент и его стили поставляются исходниками через публичный `src/index.js` и собираются Vite в составе приложений.

## Где находится код web

| Путь внутри `apps/web/src`  | Ответственность                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------- |
| `main.jsx`                  | Подключение React, BrowserRouter, TanStack Query и MSW в mock-режиме                        |
| `app`                       | Маршруты, сборка приложения, глобальные стили и тестовая среда                              |
| `pages/home`                | Обложка, краткое описание игры, терминал Мировой Машины, последние новости и блок о проекте |
| `pages/news`                | Сетка новостей, подгрузка и состояния ленты                                                 |
| `pages/section-placeholder` | Общий экран заглушки для обновлений, материалов и входа                                     |
| `pages/not-found`           | Страница 404 для неизвестных адресов                                                        |
| `entities/news`             | API-адаптер, DTO, модель загрузки, карточка и её стили                                      |
| `shared/config`             | Базовый адрес API и конфигурация разделов с заглушками                                      |
| `shared/assets`             | Общий логотип                                                                               |
| `shared/ui/site-layout`     | Шапка, мобильное меню и подвал                                                              |

Слайсы содержат сегменты по необходимости. Например, `pages/home/assets` хранит иллюстрацию первого экрана, а `entities/news` разделяет UI, модель загрузки, API и тесты. Главная и лента используют одну карточку и получают данные через публичный интерфейс `entities/news/index.js`.

## Зависимости

Полный порядок FSD: `app → pages → widgets → features → entities → shared`. В текущем web нет `widgets` и `features`.

- Импортировать можно из своего слайса и из любого нижнего слоя. Промежуточные слои можно пропускать.
- Слайсы одного слоя изолированы: `pages/home` не импортирует `pages/news`.
- Внешние потребители импортируют компоненты, конфигурацию и модель данных через публичный `index.js` соответствующего модуля. Внутри слайса используются прямые относительные импорты. Файлы изображений и шрифтов подключаются по пути к ресурсу, тестовые помощники используются в тестах.
- `app` и `shared` состоят из сегментов, а не предметных слайсов. Циклы запрещены.
- Общий пакет или новый слой выделяется при реальном повторном использовании или отдельной ответственности. Не создавать структуру заранее.

## Навигация и данные

`App.jsx` объявляет маршруты React Router в декларативном режиме.

| Маршрут      | Экран               |
| ------------ | ------------------- |
| `/`          | Главная             |
| `/news`      | Лента новостей      |
| `/updates`   | Заглушка обновлений |
| `/materials` | Заглушка материалов |
| `/login`     | Заглушка входа      |
| `*`          | Страница 404        |

Маршруты заглушек и пункты меню используют одну конфигурацию из `shared/config`. Шапка и подвал сохраняются при переходах через `Link` и `NavLink`. Активный пункт определяется маршрутом, а мобильное меню закрывается при переходе. Правила обработки прямых переходов на хостинге описаны в [README](../README.md#проверки-и-сборка).

[`WorldMachineTerminal`](../apps/web/src/pages/home/ui/WorldMachineTerminal.jsx) находится внутри `pages/home/ui`. Нативная кнопка открывает полноэкранный `<dialog>` с заглушкой описания игры. Открытие терминала сохраняет текущий URL и не вызывает запросов. Закрытие возвращает фокус кнопке без прокрутки к ней. Публичный интерфейс слайса экспортирует `HomePage`.

Один `QueryClient` на экземпляр web хранит данные TanStack Query в памяти. Главная запрашивает 3 записи через `useQuery`, список — по 12 через `useInfiniteQuery`. У этих запросов разные ключи. Данные считаются свежими минуту; после ухода со страницы неиспользуемый кэш хранится 5 минут. При возврате в список загруженные страницы видны сразу, а устаревшие данные обновляются при открытии.

Модель передаёт сигнал отмены в API-адаптер, исключает повторные ID и сохраняет карточки при ошибке подгрузки. Повторная попытка выполняется по кнопке. Короткая или пустая страница завершает список; полная позволяет запросить следующую.

`entities/news/api` выполняет HTTP-запрос и проверяет JSON по контракту. Обложки загружаются отдельно через `<img>`, относительные URL разрешаются от origin API. Карточка кадрирует фото в формате 16:9 и показывает фирменную подложку, если загрузка изображения завершилась ошибкой. Некорректный ответ API становится безопасной ошибкой интерфейса. Схемы и совместимость сервера описаны в [API-документации](../../ApiContracts/README.md).

MSW перехватывает HTTP на границе сети. Фикстуры находятся в `Frontend/mocks`. Тестовые обложки прозрачны, поэтому в mock-режиме видна подложка карточки. Точка входа подключает перехват при `DEV` и явном флаге и дожидается его готовности перед запуском React.

## Тесты и стили

- Тесты страниц и сущностей лежат внутри их слайсов в `tests`.
- `app/tests/setup.js` настраивает MSW и очистку DOM, обработчиков и URL между тестами; `App.test.jsx` проверяет композицию страниц.
- Сквозные браузерные сценарии находятся в `Frontend/tests/e2e`.
- `app/styles/global.css` подключает типографику из `@zarya/ui` и задаёт токены темы, базовые стили сетки и состояний. Стили обложки и терминала находятся в `pages/home/ui`, стили карточки в `entities/news/ui`, стили шапки и подвала в `shared/ui/site-layout`. Число колонок задаётся стилями страниц.

## Дальнейшие решения

Автоматический контроль FSD-импортов пока не выбран. Его введение требует конкретной задачи. Подробное описание игры и движок Мировой Машины остаются задачами дальнейшей разработки. Для полноценной подсистемы предусмотрены ограниченный публичный интерфейс и собственные внутренние модули.
