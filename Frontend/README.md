# Frontend

Три независимых приложения на React, JavaScript/JSX и Vite. npm workspaces объединяет приложения и общий UI-пакет. Все команды ниже выполняются из `Frontend`.

## Установка и запуск

Нужны Node.js **24.x** и npm **>=11**. Версия Node также указана в [.nvmrc](.nvmrc).

```powershell
npm.cmd ci
npm.cmd run dev:web:mock
```

| Команда                  | Адрес                          | Назначение                                  |
| ------------------------ | ------------------------------ | ------------------------------------------- |
| `npm run dev:web:mock`   | [5173](http://127.0.0.1:5173/) | Главная и новости с тестовыми данными       |
| `npm run dev:web`        | [5173](http://127.0.0.1:5173/) | Те же страницы с запросами к настоящему API |
| `npm run dev:cms`        | [5174](http://127.0.0.1:5174/) | Закрытая оболочка CMS                       |
| `npm run dev:moderation` | [5175](http://127.0.0.1:5175/) | Закрытая оболочка модерации                 |

Приложения запускаются в отдельных терминалах. Порты фиксированы, адрес привязки — `127.0.0.1`. Два режима web одновременно не запускаются. Если порт занят, остановите предыдущий экземпляр.

В обоих режимах web маршруты `/updates`, `/materials` и `/login` открывают заглушки. Иллюстрация главной и логотип входят в сборку web. Все приложения используют локальную типографику из пакета `@zarya/ui`. В публичной части Zarya Poster Black используется для крупных прописных заголовков, Zarya Text в четырёх начертаниях обслуживает текст и элементы интерфейса. В mock-режиме у карточек видна фирменная подложка.

## API и окружение

Web по умолчанию обращается к `/api/`; Vite проксирует этот префикс на `http://localhost:5257` в dev и preview. Условия подключения backend находятся в [его README](../Backend/README.md#совместимость-с-frontend).

Образец окружения: [apps/web/.env.example](apps/web/.env.example). Локальные значения задаются в `apps/web/.env.local`; после изменения перезапустите Vite.

| Переменная           | Назначение                                                                |
| -------------------- | ------------------------------------------------------------------------- |
| `VITE_API_BASE_URL`  | Base URL с API-префиксом; по умолчанию `/api/`                            |
| `VITE_ENABLE_MOCKS`  | Включает MSW только при `DEV` и значении `true`; уже задана в `.env.mock` |
| `VITE_MOCK_SCENARIO` | Сценарий MSW; по умолчанию `default`                                      |

Не задавайте `VITE_ENABLE_MOCKS` в общем окружении обычного запуска. Значения `VITE_*` доступны браузеру, секреты в них хранить нельзя. Изменение API base не меняет Vite proxy автоматически.

### Тестовые сценарии

| Сценарий          | Результат                                         |
| ----------------- | ------------------------------------------------- |
| `default`         | 26 вымышленных новостей                           |
| `empty`           | Пустой список                                     |
| `slow`            | Задержка 1500 мс                                  |
| `error`           | HTTP 503                                          |
| `network-error`   | Ошибка соединения                                 |
| `next-page-error` | Первая страница успешна, следующие возвращают 503 |

```powershell
$env:VITE_MOCK_SCENARIO = 'empty'
npm.cmd run dev:web:mock
# После остановки сервера:
Remove-Item Env:VITE_MOCK_SCENARIO
```

Неизвестный сценарий останавливает mock-запуск. Необработанные запросы выбранного API блокируются, остальные ресурсы пропускаются. MSW не моделирует аккаунты, CMS или модерацию и не включается в production.

## Проверки и сборка

```powershell
npm.cmd run check
```

Последовательность: `format:check` → `lint` → `typecheck` → `test:unit` → `build`. Каждую команду можно запускать отдельно. Типы проверяются через JSDoc/CheckJS, тесты — через Vitest и React Testing Library. Сборки лежат в `apps/<приложение>/dist`; web дополнительно проверяется на отсутствие worker и mock-маркеров.

Предпросмотр собранного публичного сайта:

```powershell
npm.cmd run preview --workspace @zarya/web
```

Адрес — [6173](http://127.0.0.1:6173/). Preview не использует моки и требует совместимого API для новостей.

На production-хостинге web отдавайте `index.html` при прямом переходе на маршруты сайта, включая `/news`, `/updates`, `/materials`, `/login` и неизвестные адреса. Запросы к `/api/` и статическим ресурсам обрабатываются отдельно. Страница «Страница не найдена» отображается на клиенте, HTTP-статус ответа задаёт хостинг.

### Браузерные тесты

```powershell
npm.cmd exec -- playwright install chromium
npm.cmd run test:e2e
```

Playwright запускает три обычных dev-сервера, для которых нужны свободные порты 5173–5175. Набор проверяет заголовок и отсутствие горизонтальной прокрутки главной при ширинах 320/768/1024/1440 px, а также закрытые оболочки CMS и модерации. Состояния ленты проверяются компонентными тестами с MSW. Интеграция с настоящим API требует отдельной проверки.

## Стиль кода

Prettier использует [.prettierrc.json](.prettierrc.json): два пробела, ориентир ширины 80, одинарные кавычки JS, двойные JSX, точки с запятой, завершающие запятые и LF. Атрибуты JSX оформляются по одному на строке. ESLint проверяет качество, обязательные скобки и запрет вложенных тернарных операторов; конфликтующие правила оформления отключены.

`npm run format:check` проверяет без записи. `npm run format` переформатирует весь frontend; для локального изменения укажите файлы явно:

```powershell
npm.cmd exec -- prettier apps/web/src/shared/ui/site-layout/SiteLayout.jsx --write
```

Зависимости, сборки и генерируемые файлы исключены через [.prettierignore](.prettierignore). Версии инструментов зафиксированы в lock-файле.

[.editorconfig](.editorconfig) задаёт UTF-8, LF и отступы пробелами. Для VS Code установите расширение Prettier; поддержка EditorConfig полезна при открытом корне репозитория. Вложенные [.vscode/settings.json](.vscode/settings.json) действуют, когда `Frontend` открыт отдельной папкой workspace. Они отключают определение отступов и задают вставку двух пробелов по Tab; форматирование при сохранении не включают.
