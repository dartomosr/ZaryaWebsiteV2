# FAQ, PressKit, описание игры и медиа

[Оглавление](../README.md) · [HTTP-примеры](EXAMPLES.md) · [Расширенные операции](EXTENDED_GUIDE.md)

Источники: [FAQ](../core/faq.yaml), [PressKit](../core/presskit.yaml), [описание игры](../core/game-summary.yaml), [медиатека](../core/media.yaml). Чтение публично, CMS доступна active Admin/Owner. Изменения требуют CSRF, существующие редакторские ресурсы также If-Match.

## Общий принцип

Информационные материалы имеют published и отдельный draft. Сохранение не публикует. Истории опубликованных версий для FAQ, PressKit, описания игры и Мировой Машины нет. `editVersion` нужен для конкурирующих правок, а не для отката к предыдущей публикации.

## FAQ

GET `/api/faq` возвращает опубликованные вопросы в порядке `order`. GET `/api/cms/faq` содержит опубликованные/черновые вопросы, `draftAction`, `orderDraft`, `orderEditVersion`. GET `/api/cms/faq/items/{faqId}` выдаёт состояние и ETag отдельного вопроса.

POST `/api/cms/faq/items` создаёт черновик. PUT `/{faqId}/draft` меняет вопрос и Markdown-ответ. POST `/{faqId}/publish` публикует, POST `/{faqId}/stage-delete` лишь подготавливает удаление. Публичный вопрос исчезает после последующей публикации этого действия, не после stage-delete.

PUT `/api/cms/faq/order/draft` сохраняет полный массив itemIds без дублей, POST `/api/cms/faq/order/publish` применяет его. Для If-Match используется `orderEditVersion`, заключённый в кавычки. После ответа 204 перечитайте состояние. Одиночная публикация проверяет текущий публичный набор. Пакет учитывает будущий набор с вопросами, создаваемыми/удаляемыми в том же commit; нельзя сначала требовать уже публичный id нового вопроса и тем самым блокировать атомарную публикацию.

Отмена подготовленного удаления без публикации и discard первого неопубликованного вопроса не имеют отдельного метода. Это открытый сценарий для уточнения, а не обещание скрытого DELETE. Для снятия stage-delete можно сохранить новый upsert-черновик, но это не эквивалент полного отсутствия изменений.

## Описание игры

GET `/api/game/summary` выдаёт shortDescription/tagline. GET `/api/cms/game-summary`, PUT `/draft`, POST `/publish` обслуживают редакторскую работу. Длинные тексты мира не добавляются сюда автоматически: они относятся к Мировой Машине. Раскрытие полученного текста в интерфейсе не требует повторного API-запроса. Само содержание игры предоставляет автор, примеры не являются лором.

## PressKit и ZIP

GET `/api/presskit` возвращает `content`, таблицу `media` с URL и `zipUrl`. Содержимое включает описание, жанр, статус релиза, платформы, логотип, изображения, внешнее видео и контакты. Frontend сопоставляет mediaId с media; не строит пути файлов самостоятельно.

GET `/api/cms/presskit` → PUT `/api/cms/presskit/draft` → GET `/api/cms/presskit/archive/preview-manifest` → POST `/api/cms/presskit/publish`. Manifest позволяет увидеть недоступные файлы и `canBuild:false`; он ничего не публикует. Публикация повторно проверяет файлы и готовность ZIP. Ошибка архивирования сохраняет предыдущую публичную версию целиком.

Для скачивания сначала GET `/api/presskit`, затем GET URL из `zipUrl`, соответствующего `/api/presskit/archive/{snapshotId}`. Адрес закреплён за неизменяемыми байтами. Старый URL нельзя переиспользовать для нового содержимого. Неизвестный/неопубликованный снимок даёт 404. Nullable zipUrl сохранён для этапной реализации; для согласования полноценной функции ZIP нужно решить, допустима ли публикация без архива вообще.

Preview-manifest относится к черновику, поэтому может включать ещё не опубликованные файлы. Публичный ZIP содержит только опубликованный снимок. Внешнее видео не скачивается сервером; допустимо перечислить его ссылку. Имена внутри ZIP относительные, без `..`, дисков, корневых и обратных слешей. Коллизии имён и размеры проверяются до сборки.

## Медиатека

POST `/api/cms/media` принимает одно поле file, JPEG/PNG/WebP до 5 MiB по текущему DTO (5 242 880 байт). GET коллекции и GET `/{mediaId}` позволяют выбрать изображение; GET `/{mediaId}/references` показывает зависимости. DELETE допускается только при отсутствии ссылок, включая черновики, сохранённые редакции и ZIP.

Ссылки проверяются атомарно с публикацией/отметкой удаления. Физическая очистка после commit не должна удалять закреплённый файл. Пустой title ссылки допустим для неполного черновика. `scope` различает published/draft/revision/archive.

MIME проверяется по байтам, а не имени или заголовку браузера. Нужны декодирование/перекодирование изображения, ограничения числа пикселей и ресурсов, очистка метаданных, запрет исполняемой разметки и безопасное серверное имя. URL неопубликованного файла не должен открывать его гостю только из-за знания id. Точная схема защищённой выдачи файлов и сроков очистки остаётся задачей backend.

Основные ошибки: 409 занятый медиафайл/нет draft, 412 конфликт версии, 413 размер, 422 недопустимое содержимое/связи, 503 временный сбой ZIP или хранилища. Верхние границы размера PressKit, массива файлов и публичных непагинируемых наборов требуют согласования до внедрения.
