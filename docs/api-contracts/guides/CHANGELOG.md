## 0.5.0-proposed: ответ списка новостей по Backend (03.11.2026)

`GET /api/news` приведён к объявленному DTO текущего `NewsController`: вместо multipart задан JSON-массив, где `url` описан как объект `PhysicalFileResult`. Для MIME обложек разрешены `image/jpeg`, `image/png` и `image/webp`. Добавлено руководство по DTO; прежнее описание multipart оставлено только как документация старого frontend-парсера. Backend и Frontend в этой задаче не менялись.

Зафиксированы ограничения текущей реализации: контроллер пока передаёт `image/jpeg` независимо от формата файла, а DTO использует `internal` свойства, которые стандартный `System.Text.Json` не сериализует. Форма OpenAPI отражает DTO, а не подтверждённое тело ответа. Совместимость Frontend с новым ответом не заявлена.

R04 закрыт отдельным [дополнением к аудиту](API_AUDIT_REPORT.md#дополнение-закрытие-r04-02112026). Исторические итоги аудита и остальные R01–R09 не пересматриваются. Обновлены связанные руководства, примеры, регрессионные тесты и снимок; сборки генерируются штатно. Общий статус HTTP-контракта остаётся proposed.

## 0.4.0-proposed: аудит контрактов и руководств (02.11.2026)

сохранены маршруты, роли и рабочий формат multipart списка новостей. Это не согласование
backend и не серверная реализация.

- 119 операций и 102 маршрута сохранены; схем стало 115 вместо 112. Добавлены AssistedRecoveryStart, WorldMachinePreviewItem и WorldMachinePreviewBundle.
- Описаны no-store, CSRF 403, If-Match 428/412, Retry-After, защита дочерних ресурсов, погашение токенов, гонки расписания/медиа/стирания текста и повтор пакета.
- Уточнены replacement PUT, области редакторских ETag, условные PublishRequest/NewComment, уникальность FAQ-порядка и фиксированные ключи пакета.
- Extended ссылается на исходный core/shared.yaml. Официальная схема OAS теперь проверяется локально по умолчанию.
- Переработаны README, источники решений, Extended; добавлены архитектура, безопасность, тематические руководства, multipart-протокол, 57 проверяемых HTTP-блоков и стандартный локальный Swagger UI.
- Новые проверки не меняют Frontend: существующий multipart-клиент вызывается тестами из каталога контрактов.

Исторические записи ниже описывают состояние **до аудита**, включая прежние утверждения

## Структурный рефакторинг 0.2 (02.11.2026, PROPOSED)

- Основная зона разделена на 12 тематических модулей в `core/`. Метаданные и явный перечень модулей находятся в `core/manifest.yaml`. Это единственные редактируемые источники основной зоны.
- `core.yaml`, `openapi.yaml` и новый `API_INDEX.md` автоматически генерируются командой `validate_contract.py --write`. Повреждённые или отсутствующие генерируемые YAML не мешают восстановлению из исходников.
- В `core/shared.yaml` выделены однократные определения `If-Match` (29 использований) и `ETag` (40 использований). В совместимых итоговых YAML они разворачиваются обратно, сохраняя полное структурное равенство прежним спецификациям без добавления схем.
- Перед изменениями зафиксированы хеши всех 106 операций и 96 схем, полных общей/основной спецификаций и защищённых исходников в `compatibility-baseline.json`. Снимок не содержит второй редактируемой копии API. Автоматическая проверка запрещает изменения любых полей итогового контракта, включая описания и ограничения; игнорируется только оформление YAML и порядок ключей объектов.
- Добавлены проверки межмодульных циклов, ссылок на генерируемые файлы, незарегистрированных модулей, коллизий и синхронизации двух сборок/индекса. Существующие проверки ограничений DTO сохранены.
- Обновлены README и сведения о количестве операций в `ZONES_AND_DECISIONS.md`. `foundation.yaml`, `common.yaml`, `extended.yaml`, backend, frontend и SQL не изменены.

**Совместимость:** 106 операций, 90 маршрутов и 96 схем сохранены. Операция `GET /api/news` с бинарным `multipart/mixed` структурно не изменена. API остаётся `PROPOSED`; реальная серверная интеграция этим рефакторингом не подтверждается. Версия API не повышалась, поскольку контракт не изменился.

## 0.2.0-proposed (02.11.2026)

**Статус основной зоны: PROPOSED. Не согласовано backend-разработчиком.** Проверки YAML/OpenAPI не означают, что сервер реализован или интеграция подтверждена.

### Изменения относительно 0.1

- Основная зона расширена с одной операции до 73 операций на 60 маршрутах. Добавлены предложенные методы новостей, обновлений, комментариев, реакций к новостям, CMS, модерации, FAQ, PressKit, описания игры и медиаресурсов.
- Канонический `openapi.yaml` пересобран из локальных `common.yaml`, `foundation.yaml`, `core.yaml`, `extended.yaml`: 33 фундаментальные + 73 основные операции, всего 106 на 90 маршрутах. Внешних `$ref` нет. Расширенная зона остаётся пустой.
- Существующая операция `GET /api/news` сохранена структурно целиком: `multipart/mixed`, первая часть JSON `NewsPage`, затем бинарные изображения, связанные по `Content-ID` / `coverPartId`. Этот формат предварительный и требует согласования с backend. Входное предложение с JSON-ответом на этом маршруте отклонено как несовместимое с текущим frontend/MSW.
- Входные схемы 3.1 приведены к OAS 3.0.3: 9 nullable-объединений типов, 51 null-альтернатива `oneOf`, одно `const: true`. Сохранены обязательные поля, значения перечислений и ограничения; добавлены регрессии для nullable-ссылок, границ пагинации и строгого подтверждения удаления.
- В валидатор добавлена воспроизводимая сборка `--write`, обнаружение повторных YAML-ключей и коллизий путей/методов, шаблонов маршрутов, тегов, компонентов и идентификаторов операций. Проверяется полное структурное совпадение канонического файла с исходниками; доступна официальная OAS JSON Schema через `--oas-schema`.
- README обновлён: описаны зоны, команды сборки/проверки, преобразования схем и ограничение описания multipart-ответа в OAS 3.0.3.

### Сохранённые границы

`foundation.yaml`, `common.yaml`, `extended.yaml`, backend, SQL и frontend не изменены. Авторизация и роли остаются в фундаменте. Комментарии предусмотрены только для новостей и обновлений, реакции только для новостей. Сохранение черновика не публикует его; восстановление из корзины не делает материал публичным. Публичный PressKit не должен выдавать неопубликованное содержимое. Реализация сервера, данные и продвинутые методы зоны 3 не добавлялись.

### Ограничения

Бинарное тело `multipart/mixed` описано в OpenAPI как `string/binary`; порядок частей и связи `Content-ID` требуют проверки реального протокола. Разбор multipart в Swagger UI не гарантирован. Nullable-составные схемы могут отображаться по-разному в генераторах. Локального Swagger UI нет. Реальный ASP.NET Core API и интеграционные сценарии не проверены; новые URL/DTO ещё требуют согласования.
