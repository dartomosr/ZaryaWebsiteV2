**Откройте `openapi.yaml`** в редакторе OpenAPI или Swagger UI: это **единый самостоятельный файл**, уже собранный из зон и общих схем. Отдельные файлы нужны для дальнейшего изменения разделов, после чего единый файл обновляется сборкой.

> OpenAPI — это **описание HTTP-операций и форматов JSON**, не отдельная программа между frontend и backend. Сервер ASP.NET Core реализует эти операции по контракту. Использование OpenAPI не требует переписывать архитектуру ASP.NET Core/EF Core/SQL Server.

## Правило трёх зон

**1. Фундамент:** после двустороннего согласования максимально стабильный; изменение ломающее клиентов требует версии/миграции. **2. Основной:** рабочий контракт, корректировки согласуются. **3. Расширенный:** допускает более свободную переработку до заморозки конкретного модуля. Это **не** три сервера и **не** три уровня обязательности функций.

В этом комплекте **подробно спроектирована только зона 1**. Вторая содержит лишь уже известный HTTP-формат `GET /api/news`; третья пока не имеет endpoint-ов. Это намеренно: мы не подменяем дальнейшее проектирование выдуманными DTO.

## Как получить ответ сервера для frontend

1. `GET /api/auth/csrf` — получить `token` и связанную анонимную cookie.
2. На `POST /api/auth/login` отправить JSON с `login` и `password`, добавить `X-CSRF-Token: <token>`.
3. `GET /api/auth/session` — получить состояние сессии (`anonymous`, `email_verification_required`, `two_factor_required`, `two_factor_setup_required`, `active`).
4. Если `two_factor_required`, отправить код на `POST /api/auth/2fa/challenge`. Если `email_verification_required`, доступен только контур подтверждения почты. Если сотруднику требуется настроить TOTP, использовать `/api/auth/2fa/setup` и `/confirm`.
5. После смены/повышения сессии **получить новый CSRF-токен**. В служебных приложениях frontend скрывает интерфейс до подтверждения роли и прохождения 2FA; backend независимо проверяет **каждый** запрос.

Минимальный пример результата `GET /api/auth/session` без входа:

```json
{
  "state": "anonymous",
  "user": null,
  "capabilities": {
    "canComment": false,
    "canReact": false,
    "canUseCms": false,
    "canModerate": false,
    "canManageUsers": false
  },
  "expiresAt": null,
  "nextStep": null
}
```

### Что значит `username`

В старом ТЗ разрешён вход по **email или имени пользователя**, при этом публичное отображаемое имя может меняться. Во избежание неоднозначности здесь **предложено** технически разделить уникальный `username` (логин, латинские буквы/цифры/подчёркивание, 3–30 символов) и `displayName` (имя под комментариями, может совпадать у разных пользователей). `username` не меняется в обычном редакторе профиля. **Это [ПРЕДЛОЖЕНИЕ], не подтверждённое отдельно продуктовым решением**; если команда предпочитает иной способ идентификации, обновить контракт до заморозки зоны 1. API возвращает все идентификаторы как непрозрачные строки, независимо от внутреннего типа в SQL Server.

## Жизненный цикл и изменения

- **До подтверждения обеих сторон** все HTTP-маршруты, имена JSON-полей, cookie и схемы здесь — `PROPOSED`, даже когда функциональность утверждена.
- При согласовании записать в `CHANGELOG.md` версию, дату, участников и изменённые поля; затем синхронизировать frontend API-адаптеры, MSW и тесты.
- Не менять уже работающий frontend `GET /api/news` без отдельного согласования; этот метод оставлен в `core.yaml` в существующей предварительной форме.
- Не менять backend/SQL или исходный репозиторий из-за этого пакета: создана **только документация/API-предложение**.
- После реализации сравнивать реальные ответы ASP.NET Core с `openapi.yaml` и интеграционными сценариями, а не считать YAML доказательством работоспособности.

## Совместимость с ASP.NET Core

ASP.NET Core может **генерировать собственный OpenAPI** из реализованных маршрутов, а мы можем сравнивать его с нашим согласованным контрактом. Встроенная генерация доступна начиная с .NET 9; в .NET 10 поддержка OpenAPI 3.1 предусмотрена напрямую. Для интерактивного UI (Swagger UI или Scalar) может потребоваться отдельное подключение. **Точная версия .NET в предоставленных документах не подтверждена**, поэтому данный пакет не предписывает команду установки конкретного NuGet-пакета.

Полезные официальные источники: [Microsoft Learn: Generate OpenAPI documents](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/minimal-apis/aspnetcore-openapi), [OpenAPI Specification 3.1.1](https://spec.openapis.org/oas/v3.1.1.html).
