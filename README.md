# Вебсайт «ЗАРЯ»

Официальный сайт игры **«ЗАРЯ: Марш Революции»**. Сайт предназначен для знакомства с игрой, публикации новостей и обновлений, общения с игроками и предоставления материалов для прессы.

## Текущее состояние

Созданы три отдельных React-приложения с автоматическими проверками и сборкой. На странице `/news` реализованы опубликованные новости, кнопка «Показать ещё», загрузка, пустой список, ошибки и повторная попытка. Для независимой разработки доступен явно включаемый режим MSW с вымышленными данными. CMS и модерация закрыты до подключения серверной проверки доступа.

Остальные возможности ниже запланированы. Контракт API новостей предварительный. Интеграция с реальным сервером пока не проверена; серверный код и SQL-скрипты не создавались.

## Возможности

| Часть проекта | Планируемые функции |
| --- | --- |
| Публичный сайт | Описание игры, FAQ, новости, обновления со списками изменений, PressKit с изображениями и ZIP-архивом |
| Учётная запись | Регистрация, вход и выход, профиль, изменение имени, email, пароля и аватара |
| Общение | Комментарии к новостям, удаление собственных комментариев, положительные и отрицательные реакции с возможностью снятия |
| CMS | Создание, редактирование и удаление новостей и обновлений; черновики, публикация и загрузка изображений |
| Модерация | Просмотр комментариев и удаление с явным подтверждением |

Публичный сайт рассчитан на экраны от **320 px**, CMS и модерация на рабочую ширину от **1024 px**. На главной предусмотрено до трёх последних опубликованных материалов каждого типа. Визуальное оформление: тёмная палитра, белый текст, жёлто-оранжевые и фиолетовые акценты.

**Подписки, рассылки и почтовые уведомления исключены из текущей версии.** Email сохраняется как поле учётной записи.

## Архитектура

В одном репозитории размещаются клиентская и серверная части.

- **Клиентская часть:** три независимых приложения на **React + JavaScript/JSX + Vite**, объединённые через npm workspaces. Публичный сайт, CMS и модерация имеют собственные интерфейсы и сборки.
- **Серверная часть (предварительная схема):** единый **ASP.NET Core API**, **Entity Framework Core**, **Microsoft SQL Server** и файловое хранилище изображений.
- **Обмен данными:** браузер обращается только к API. Для данных используется JSON, для загрузки изображений предусмотрен `multipart/form-data`.
- **Доступ:** сессию определяет серверная cookie. Перед отображением CMS и модерации API должен подтвердить роль `Admin` или `Moderator`; окончательный контроль прав выполняется на сервере.
- **Контент:** описание игры, FAQ и PressKit входят в frontend-сборку. Новости, обновления, пользователи, комментарии и реакции обслуживаются через API.

Серверная часть находится на этапе проектирования. Схема БД, окончательные адреса API, DTO и параметры cookie/CORS/CSRF пока не определены.

## Структура репозитория

```text
Frontend/
  apps/
    web/                       # публичный сайт
    cms/                       # административное приложение
    moderation/                # модерация комментариев
  tests/e2e/                   # браузерные сценарии
  mocks/                       # вымышленные данные и обработчики MSW
  scripts/verify-web-build.js   # проверка отсутствия моков в сборке
  package.json                 # команды и npm workspaces
  README_Frontend.md           # подробная инструкция frontend
  ARCHITECTURE_Frontend.md     # архитектура и требования
  AGENTS_Frontend.md           # правила работы над frontend
Backend/                       # место для серверной части; пока только .gitkeep
README.md                      # обзор проекта
```

В `apps/web/src` папка `app` отвечает за выбор страницы, `pages` за интерфейсы, `api` за запросы и JSDoc-контракты, `styles` за оформление, `test` за настройку тестов. CMS и модерация сохраняют собственные сборки. Папки функциональных модулей и общих компонентов добавляются по мере появления реальной необходимости.

Компоненты всегда получают данные через API-слой. В mock-режиме MSW перехватывает эти же HTTP-запросы, а при подключении backend они уходят на сервер.

## Предварительный контракт новостей

**Статус: предварительная версия для разработки клиентской части.** Все перечисленные URL и DTO могут уточняться при интеграции; они не задают структуру таблиц БД.

| Часть | Предварительное решение |
| --- | --- |
| Запрос | `GET /api/news?page=1&pageSize=12`, публичное чтение опубликованных новостей |
| Параметры | `page`: целое от 1; `pageSize`: целое 1–50; значения по умолчанию 1 и 12 |
| Карточка | `id`, `title`, `summary`, `coverUrl` (URL или `null`), `publishedAt` (ISO 8601 UTC); `id` является непрозрачной строкой |
| Ответ | `{ items, page, pageSize, nextPage }`; `nextPage: null` завершает пагинацию; пустая страница возвращает `200` |
| Порядок | Время публикации по убыванию, при совпадении даты `id` по возрастанию |
| Ошибки | `400`: `INVALID_QUERY` и ошибки параметров; `503`: `SERVICE_UNAVAILABLE`; общий формат `{ code, message, errors? }` |
| Настройка адреса | `VITE_API_BASE_URL` включает API-префикс; по умолчанию `/api/` |

Полное описание: [раздел 8.3 архитектуры](Frontend/ARCHITECTURE_Frontend.md#83-предварительный-контракт-списка-новостей-и-msw). Типы и проверка ответов находятся в [JSDoc-контракте](Frontend/apps/web/src/api/news.contract.js) и [API-слое](Frontend/apps/web/src/api/news.js). Прохождение тестов с MSW не подтверждает совместимость с реальным сервером.

## Локальный запуск

Требуются **Node.js 24.x** и **npm >=11**. Из корня репозитория:

```powershell
cd Frontend
npm ci
npm run dev:web
```

Остальные приложения запускаются из `Frontend` в отдельных терминалах:

| Приложение | Команда | Адрес |
| --- | --- | --- |
| Публичный сайт | `npm run dev:web` | [127.0.0.1:5173](http://127.0.0.1:5173) |
| CMS | `npm run dev:cms` | [127.0.0.1:5174](http://127.0.0.1:5174) |
| Модерация | `npm run dev:moderation` | [127.0.0.1:5175](http://127.0.0.1:5175) |

Для разработки новостей без backend выполните `npm run dev:web:mock` из `Frontend` и откройте `/news`. Будет виден индикатор «Тестовые данные». Обычный `npm run dev:web` не активирует MSW: новости запрашиваются у настроенного API. Пример конфигурации находится в `Frontend/apps/web/.env.example`.

MSW 3.0.3 подключён официальным плагином `msw/vite`: worker обслуживается только при разработке и не копируется в production. Сценарии: `default`, `empty`, `slow`, `error`, `network-error`, `next-page-error`. Например, в PowerShell перед mock-запуском задайте `$env:VITE_MOCK_SCENARIO = "empty"`; после работы удалите настройку командой `Remove-Item Env:VITE_MOCK_SCENARIO`. Подробный контракт и ограничения описаны в документации frontend.

Все mock-материалы вымышленные. Неизвестные запросы внутри выбранного API-origin и API-префикса блокируются с явной ошибкой; ресурсы Vite и приложения пропускаются. Сценарии не моделируют серверную авторизацию и не заменяют проверку прав. Не храните секреты в `VITE_*`: эти переменные доступны браузерной сборке.

## Проверки и сборка

Все команды выполняются из `Frontend`:

| Команда | Назначение |
| --- | --- |
| `npm run lint` | Статический анализ ESLint |
| `npm run typecheck` | Проверка JavaScript через CheckJS и JSDoc без перехода на TypeScript |
| `npm run test:unit` | Быстрые тесты Vitest и React Testing Library |
| `npm run build` | Сборка всех трёх приложений в `apps/<имя>/dist` |
| `npm run check` | Последовательный запуск всех перечисленных проверок и сборки |
| `npm run test:e2e` | Отдельные браузерные сценарии Playwright |

Playwright подготовлен для проверки оболочек и экранов 320/768/1024/1440 px. Перед первым запуском требуется `npx playwright install chromium`; E2E-команда самостоятельно запускает три dev-сервера. Браузерные проверки выполняются отдельно от `npm run check`.

Последняя проверка (28.10.2026): ESLint, CheckJS, 18 тестов и сборки трёх приложений прошли успешно. Проверено отсутствие mock-worker и маркеров тестовых обработчиков/данных как в обычной production-сборке, так и в сборке с `--mode mock`. Браузерные сценарии и интеграция с реальным сервером пока не проверены.
