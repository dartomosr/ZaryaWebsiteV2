# API-контракт

Проект единого HTTP API публичного сайта, CMS и модерации в формате OpenAPI 3.0.3. Каноническая сборка — [openapi.yaml](openapi.yaml), операции перечислены в [генерируемом индексе](guides/API_INDEX.md).

Статусы операций определяются `x-stability`; текущие операции помечены `proposed`. Реализованный сервер описан отдельно в [Backend/README.md](../Backend/README.md). Контракт содержит больше возможностей, чем сервер и интерфейсы.

## Найти нужную операцию

| Источник | Содержимое |
| --- | --- |
| [foundation.yaml](foundation.yaml) | Аккаунты, сессии, роли, подтверждение email и восстановление доступа |
| [core/manifest.yaml](core/manifest.yaml) и модули `core` | Новости, обновления, CMS, комментарии, реакции, модерация и материалы сайта |
| [extended.yaml](extended.yaml) | Мировая Машина, пакетная публикация, архивы и сравнение редакций |
| [shared/common.yaml](shared/common.yaml), [core/shared.yaml](core/shared.yaml) | Общие схемы, параметры и ответы |

Это части одной спецификации, а не отдельные серверы. Точные URL, DTO, права и коды ошибок смотрите в YAML. [HTTP-примеры](guides/EXAMPLES.md) показывают последовательности запросов; [список новостей](guides/NEWS_RESPONSE.md) поясняет границу с текущим frontend.

## Просмотр

Для инструментов нужны Python **3.12+**, PyYAML и jsonschema. Можно использовать рабочее окружение проекта или создать новое из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install PyYAML jsonschema
.\.venv\Scripts\python.exe -B ApiContracts/tools/serve_docs.py
```

Откройте [Swagger UI](http://127.0.0.1:8088/viewer/). Выполнение запросов отключено. Для загрузки интерфейса нужен доступ к CDN; YAML и проверки работают локально. Остановка — `Ctrl+C`.

Если существующая `.venv` ссылается на отсутствующий Python, используйте исправное окружение; скрипты не требуют именно этого имени каталога.

## Проверки

Из корня репозитория, с рабочим Python-окружением:

```powershell
.\.venv\Scripts\python.exe -B ApiContracts/tools/validate_contract.py
.\.venv\Scripts\python.exe -B -m unittest discover -s ApiContracts/tests -p 'test_*.py' -v
.\.venv\Scripts\python.exe -B ApiContracts/tools/check_docs.py
```

Проверяются сборка YAML, ссылки, схемы, совместимость и HTTP-примеры. Проверки не отправляют запросы на сервер и не подтверждают реализацию его прав, транзакций или безопасности.

`tests/multipart.test.js` проверяет прежний формат клиента и несовместим с текущим JSON-адаптером. Его конфигурация Vitest сохранена, но этот набор не следует использовать для приёмки текущего списка новостей. Актуальные клиентские тесты запускаются через `npm run check` в Frontend.

## Изменить контракт

1. Найдите операцию в индексе и измените YAML-исходник. Новый Core-модуль зарегистрируйте в manifest.
2. Проверьте потребителей, права, ошибки и совместимость. Согласуйте изменение; не подгоняйте контракт под случайный ответ текущего сервера.
3. Если меняется зафиксированная редакция, после ревью обновите снимок с конкретным основанием из каталога `ApiContracts`:

   ```powershell
   ..\.venv\Scripts\python.exe -B tools/update_baseline.py --reason "Основание согласованного изменения"
   ```

4. Из корня пересоберите производные файлы и повторите проверки:

   ```powershell
   .\.venv\Scripts\python.exe -B ApiContracts/tools/validate_contract.py --write
   ```

**Не редактировать вручную:** `core.yaml`, `openapi.yaml` и `guides/API_INDEX.md`. Снимки совместимости и исторические JSON-фикстуры нужны тестам; их нельзя удалять или перезаписывать ради прохождения проверки.

HTTP-блоки с привязками `operationId` редактируются в `guides/EXAMPLES.md`. После изменения пересоберите `EXAMPLES.http`:

```powershell
.\.venv\Scripts\python.exe -B ApiContracts/tools/check_docs.py --write-http
```

## При подключении новых функций

Сервер обязан проверять сессию, состояние аккаунта и доступ к объекту в каждой защищённой операции. Cookie/CORS/CSRF, origins и сроки сессий согласуются с развёртыванием; скрытие клиентского интерфейса не заменяет эти проверки. Секреты не передаются в `VITE_*` и не записываются в логи.

Соблюдайте `If-Match` и версии там, где они заданы, и не повторяйте изменяющий POST автоматически после потери ответа без предусмотренного механизма идемпотентности. JSON Schema проверяет структуру; она не доказывает транзакционность, права или безопасность файлов. Конкретные требования находятся в описаниях операций, без отдельной дублирующей матрицы.
